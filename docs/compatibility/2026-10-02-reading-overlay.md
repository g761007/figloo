# 讀取時的遮罩與背景暫停

狀態：已實作，兩個階段在 Arc 驗證；逾時後延後收回只以單元測試驗證  
日期：2026-10-02  
規劃：[讀取時的遮罩與暫停](../plans/2026-10-02-reading-overlay.md)

## 行為

| 情境 | 行為 |
|---|---|
| `snapshot_layer` 讀取期間 | 截圖完成後，Figma 頁面上出現半透明遮罩：標題、進度（走訪時的圖層數，逐一讀取時的「Read N of M layers」與預估剩餘時間）、說明與「Stop」按鈕。文字為英文 |
| 點擊、捲動或按鍵落在遮罩上 | 遮罩攔下，不傳給 Figma，也不算使用者介入；Esc 以外的按鍵一律忽略 |
| 按「Stop」或 Esc | 中止，回報 `USER_INTERRUPTED`，訊息說明是使用者停止的；完整收回圖層面板、還原選取與捲動位置 |
| 遮罩以外的輸入 | 照原有規則中止，收回展開的圖層，保留使用者的新選取 |
| 讀取中分頁進入背景 | 暫停，遮罩顯示「Paused」；回到畫面後從中斷的圖層繼續，分頁在背景時讀到的那個圖層重讀。暫停時間算在 180 秒的上限內 |
| 分頁在背景時用完時間 | 回報 `BUDGET_EXCEEDED`，訊息說明分頁在背景；分頁回到畫面時收回圖層面板、還原選取。若使用者在那之前已操作 Figma、換了頁面或檔案，或有其他操作正在進行，就不再還原 |

遮罩放在 closed Shadow DOM 裡，掛在 `document.documentElement` 下，z-index 為允許的最大值；樣式以 CSSOM 設定，不受 Figma 的 CSP 限制。Figloo 對圖層列與展開箭頭直接派發事件，不經過遮罩。截圖在遮罩出現之前完成。

## 驗證

| 項目 | 環境 | 結果 |
|---|---|---|
| 單元測試 | happy-dom，擷取的 Figma 圖層面板 | 遮罩的建立與移除、closed Shadow DOM、焦點、Stop 與 Esc、其他按鍵忽略、事件不傳給 Figma、進度文字與剩餘時間；Stop 走完整還原並回報專屬訊息，遮罩上的輸入不算介入；背景時暫停、繼續與期限；點擊在切到背景時遺失會在回來後重做；背景中結束後延後收回，以及使用者先操作或換檔案時放棄。關鍵行為都以變異測試確認測試會失敗 |
| 遮罩與 Stop | Arc 1.167.0，macOS 27.0，已登入、檢視權限，203 個圖層的 frame | 遮罩出現，進度文字隨讀取更新；截圖中沒有遮罩；按「Stop」約 12 秒時中止，圖層面板收回、選取還原；按 Esc 約 9 秒時中止，選取還原 |
| 背景暫停 | 同上 | 讀取中切到其他分頁約數秒再切回：讀取暫停後繼續完成，共 57 秒（平時約 25 秒），203 個圖層全部讀到，多 3 次 UI 操作（重做的步驟）；短暫切走一次：正常完成，重做 1 步 |

## 已知限制

1. 在 Arc 上沒有實測「分頁在背景直到逾時，回到畫面後收回」，只有單元測試。
2. 在 Arc 上沒有確認點擊遮罩時 Figma 是否有反應。遮罩在自己身上攔下事件，但 Figma 掛在 window 捕獲階段的監聽仍會先看到這些事件。
3. 逾時後還原選取時，若使用者原本選取的圖層不在圖層面板的可見範圍內，捲動過去的步驟會因時間已用完而停止，選取可能沒有還原。這項限制在加入遮罩之前就存在，分頁在畫面上逾時時也一樣。
4. 進度的剩餘時間以最近 20 個圖層的平均計算，遇到需要較久的圖層時會有落差。
