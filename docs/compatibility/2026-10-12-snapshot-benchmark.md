# 快照的效能基準

狀態：完成，v0.7.0 的 M2
日期：2026-10-12
依據：[v0.7.0 計畫](../plans/2026-10-12-v0.7.0-performance.md)

## 做法

- `pnpm bench:snapshot` 對同一個 frame 以 `refresh: true` 拍 3 次快照，每次都重新讀取 Figma，取各階段的中位數。只記層數與毫秒數。
- 小型 frame 用登入版 canary 的 profile（headless Chromium，視窗 1600×1000）在公開的 canary 檔上量；大型 frame 用 `--attach` 接使用者自己的 Arc，在私人測試檔上量，檢視權限、已開啟「Adapt content for screen readers」。
- 使用者原本要選 200 到 300 層的畫面，實際選到的是 605 層，所以沒有中型的數字。

## 結果

每個 frame 3 次的中位數：

| | canary 0:2 | canary 0:78 | 私人測試檔的畫面 |
|---|---|---|---|
| 瀏覽器 | headless Chromium | headless Chromium | Arc |
| 層數 | 39 | 59 | 605 |
| 總時間 | 7.8 秒 | 9.6 秒 | 75.2 秒（3 次為 80.9、75.2、73.3 秒） |
| 每層平均 | 200 ms | 163 ms | 124 ms |
| 截圖準備 | 3.4 秒 | 3.1 秒 | 3.4 秒 |
| 其中等縮放提示消失 | 2.3 秒 | 2.3 秒 | 2.3 秒 |
| 走訪（展開圖層） | 0.5 秒 | 0.6 秒 | 10.9 秒（18 ms／層） |
| 逐層點選 | 1.4 秒（37 ms／層） | 2.4 秒（41 ms／層） | 25.5 秒（42 ms／層） |
| 等屬性面板 | 1.2 秒（31 ms／層） | 0.9 秒（16 ms／層） | 23.7 秒（39 ms／層） |
| 其中等滿 400 ms（相鄰圖層長得一樣） | 1 次 | 0 次 | 23 次，至少 9.2 秒 |
| 收回展開的圖層與還原選取 | 0.5 秒 | 0.6 秒 | 10.2 秒（17 ms／層） |
| 還原畫面 | 0.6 秒 | 1.7 秒 | 0.5 秒 |

- 在圖層面板找列、解析屬性面板與等 mirror，605 層加起來不到 0.8 秒；三個 frame 都沒有等滿 300 ms 的 mirror，也沒有等滿 500 ms 的屬性面板。
- 各階段加總與總時間相差不到 1%。
- 605 層一次呼叫就讀完，沒有用到分次續讀。

## 時間花在哪裡

- 小型 frame：固定成本為主。等縮放提示消失約 2.3 秒，占 25% 到 30%。
- 大型 frame：每層約 80 ms 的點選與等屬性面板占 66%，其中有 23 次是相鄰圖層長得一樣而等滿 400 ms；走訪時展開圖層、結束時再收回，合計約 21 秒，占 28%。
- 和 2026-10-01 的數字（278 層 38.8 秒，逐層讀取每層約 110 ms）比較，這次每層的點選加等屬性面板約 83 ms；畫面與當時的系統狀態都不同，只能大致對照。

## 減少等待的候選（M3）

依可能省下的時間排列，以 605 層的畫面估計：

1. 相鄰圖層長得一樣時的 400 ms：最多約 9 秒。需要一個屬性面板已經換成新圖層的直接訊號，例如面板的 DOM 確實重新渲染過。
2. 走訪的展開與結束時的收回：約 21 秒。可以研究一次展開或收回整棵子樹的方式，但要保留使用者原本展開的圖層。
3. 等縮放提示消失：每次 2.3 秒，小型 frame 的比例最高。提示不在裁切範圍內時可以不等。
4. 還原畫面：0.5 到 1.7 秒。
5. 點選與等屬性面板的其餘部分，每層約 60 ms，大多是 Figma 本身的渲染時間，可以縮短的空間不確定。

## 沒有驗證

- 200 到 300 層的中型 frame。
- 同一個 frame 在 Arc 與 headless Chromium 的差異。
- 其他電腦與網路狀況下的數字。
