# 頁面快照第一階段：adapter 的完整讀取

狀態：第一階段完成。分頁內的讀取以注入 adapter 的方式在 Arc 驗證；經由 service worker 與 MCP 的完整路徑留到第二階段  
日期：2026-10-01  
規劃：[頁面地圖與快照](../plans/2026-10-01-page-map-research.md)

## 新增的內容

| 項目 | 說明 |
|---|---|
| Bridge 操作 `snapshot_layer` | Service worker 先以 `capture` 的流程截取 root，再請分頁執行 `read_subtree`，最後算出 root 在截圖中的位置，以及每個設計稿像素等於截圖中的幾個像素。快照排隊或執行期間，同一個分頁的其他操作回傳 `BUSY` |
| 分頁內的 `read_subtree` | 走訪、逐一讀取屬性與位置、收回與還原 |
| 上限 | 400 個圖層、180 秒，其中保留 15 秒給逾時後的收回、還原選取與回傳。UI 操作上限是每個允許的圖層 3 次，也就是 1,200 次 |
| `capture` 的結果 | 新增 `crop`：截圖實際涵蓋的 viewport 範圍，單位是 CSS 像素 |
| 錯誤碼 `INSIDE_INSTANCE` | Root 在 instance 裡面時回報 |

每個圖層記錄：ref、名稱、類型、深度、父層、在同層中的順序、instance 有沒有子層、是否隱藏、相對 root 的位置與大小及其來源、屬性面板的全部區塊，以及設計師設定的匯出格式。

## 讀取流程

1. 截圖：縮放到 root（Shift+2）、取消選取、截圖、還原選取。之後畫面不再移動。
2. 確認 root 不在 instance 裡面。
3. 一次展開的走訪：由 root 往下依序讀圖層列，遇到收合且不是 instance 的圖層就展開；使用者自己展開的 instance，其子層直接略過。超過 400 個就停止，改為列出 root 的直接子層。
4. 依圖層面板的順序逐一選取，讀取屬性面板、匯出區塊與 mirror。每次選取時 mirror 放入的圖層都一併記下。
5. 收回自己展開的圖層，還原選取與捲動位置。

第 3 與第 4 步不合併：走訪只占讀取時間的 16%，而分開走訪可以在逐一讀取之前就知道子樹是否過大。

使用者在讀取中點擊、按鍵或捲動時，快照中止，不留下部分結果，並收回自己展開的圖層；使用者在收回期間再次操作就停止收回。選取與捲動位置保留使用者的操作，不改回原本的狀態。其他工具被中止時面板維持原狀，快照因為一次展開的圖層很多，所以改為收回。

## 實測

環境：Arc 1.166.0，已登入、檢視權限，英文 UI，使用者提供的私人測試檔中一個 393×852 的頂層手機畫面 frame。以 AppleScript 把 adapter 注入分頁執行。`captureVisibleTab` 只有 service worker 能呼叫，所以這裡沒有實際截圖，但縮放、裁切範圍的量測與還原選取都有執行。

| 項目 | 結果 |
|---|---|
| 圖層數 | 278 個，其中 instance 32、文字 55、隱藏 33；最大深度 11 |
| 總時間 | 38.8 秒：截圖 3.5 秒、走訪 5.6 秒，其餘是逐一讀取，每個圖層約 0.11 秒。第一次是 40.6 秒 |
| UI 操作 | 491 次展開、收合與捲動，另外每個圖層選取一次 |
| 還原 | 面板列數、捲動位置與選取都和開始時相同；之後連續讀取 20 輪也是如此 |
| 畫面 | 讀取前後 root 在畫面上的位置完全相同，所以從圖層面板選取不會移動畫面 |
| 截圖對位 | 裁切範圍正好是 root 四周各留 12 px；縮放比例 0.9260，工具列顯示 93% |
| 屬性 | 抽樣 16 個圖層，涵蓋 13 種類型、root 與清單最末端的圖層，和 `inspect_nodes` 的結果完全相同 |
| 位置來源 | mirror 223 個，面板 30 個（都是文字），未知 25 個（由 auto layout 決定位置的文字） |
| 位置與面板比對 | 沒有旋轉、而且面板有 Top 或 Left 的 120 個圖層中，117 個相差 0.1 px 以內；比 root 還大的一張圖片差 0.31 px；兩個 vector 差 4.5 px，見下文 |
| 大小與面板比對 | 223 個以 mirror 量測的圖層中，轉了 90° 的 3 個箭頭除外，其餘相差都在 0.5 px 以內，只有比 root 大的那張圖片超過 0.15 px |
| 超過上限 | 上限設為 50 時，1.6 秒就停止並回傳 root 的 4 個直接子層 |
| 時間上限 | 設為 8 秒時回報 `BUDGET_EXCEEDED`，面板與選取都還原；收回另外花了約 5 秒，所以時間上限內預留了 15 秒 |
| 中止 | 讀取到第 16.5 秒時，使用者在畫布上點一下：回報 `USER_INTERRUPTED`，展開的圖層全部收回，選取保留使用者點到的圖層。這也是第一次在 Arc 以真實點擊驗證中止的偵測 |

## Figma 的實際行為

### 隱藏圖層

- 隱藏的圖層，以及隱藏圖層裡面的每個圖層，圖層列自己的 style 會加上 `color: var(--color-text-disabled)`，名稱因此變淡。這和選取無關：同樣的 33 列在選取與未選取時都有；M0 擷取的 fixture 中，一個未選取的圖層列也有它。
- 屬性面板對隱藏圖層沒有任何不同的內容。
- Mirror 仍然放入隱藏圖層並給出位置。所以「mirror 沒有位置的圖層多半是隱藏的」這個推測不成立。
- 圖層面板上的眼睛圖示沒有逐一核對。判斷依據是：變淡的圖層包含一個標註群組與兩張和畫面一樣大的參考圖，使用者也確認這頁可能有隱藏圖層。使用者表示隱藏圖層不是重點，所以不再深入。

### 匯出設定

- 278 個圖層中有 16 個帶設計師的匯出設定，格式有 PNG 1x、2x、4x 與 SVG 1x。
- 選取後約 65 到 100 ms，匯出區塊才換成新圖層的內容，在那之前仍是前一個圖層的。其中 9 個圖層，切換前的狀態會被「沒有設定列，或按鈕寫著這個圖層」的規則接受：前一個圖層沒有設定時，「沒有設定」會被直接接受；前一個圖層的名稱與它開頭相同時，舊設定也會被當成它的。
- 等屬性面板確認切換後再讀，278 個圖層的匯出狀態在之後 300 ms 內都沒有再變；有設定的 16 個，按鈕也都寫著該圖層的名稱。所以快照在面板確認切換後讀取匯出設定；面板沒有確認時，或有設定但按鈕寫的不是這個圖層時，記為 null。

### Mirror 與面板的位置

- 線段的外框高度是 0，轉 90° 之後則是寬度為 0。原本讀取 mirror 時要求寬高都大於 0，所以漏掉了 6 個線段與箭頭。現在只要有一邊大於 0 就記錄，`get_visual_neighbors` 也因此能量到線段。
- 面板的 Top 與 Left 是圖層變形前原點的位置。旋轉 -180° 的兩張圖片，面板的 Top 比畫面上的外框多一個高度。所以有旋轉的圖層，不用面板的值推算位置。
- 兩個沒有旋轉的 vector，mirror 的位置比面板多 4.5 px，正好是它們的高度，可能是翻轉過。哪一邊和畫面一致尚未確認。
- 文字圖層不在 mirror 中，與先前相同。

### 時間

- 逐一讀取每個圖層約 0.11 秒，比研究時用 `inspect_nodes` 分批讀取的 0.23 秒快。
- 照這個速度，400 個圖層約需 1 分鐘。

## 單元測試

- 圖層樹的一次展開走訪，6 項：依面板順序只讀一次、每個收合的圖層只展開一次、不展開 instance 並略過使用者展開的 instance、收合的 root、剛好等於與超過上限、使用者中途介入。
- 位置換算，6 項：mirror、小數縮放比例的誤差、文字依最近的 frame 換算且群組不算、未知的位置、沒有 mirror 時與群組當 root 時、高度為 0 的線段。
- 截圖，2 項：實際涵蓋的範圍，以及 root 在縮小後截圖中的位置。
- 隱藏圖層列，1 項，使用 M0 擷取的標記。
- 協定，2 項。

全部 168 項通過，原本 151 項。

3. 讀取中 Figma 分頁切到背景時的中止。沿用現有的 `TAB_IN_BACKGROUND` 偵測，快照中未實測。
4. Group 以外不算 frame 的類型，例如布林運算。目前只有 Group 不算 frame。
5. 有旋轉的文字圖層，這頁沒有。
6. 兩個 vector 的 4.5 px 差異。
