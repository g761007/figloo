# 相鄰元件與多選錨點

狀態：已實作。Adapter 的邏輯以注入方式在 Arc 驗證；經由 MCP 的完整路徑，以這個工作階段的 Claude Code 驗證了多選與相鄰元件的呼叫流程  
日期：2026-10-01  
規劃：[相鄰元件搜尋與多選錨點](../plans/2026-10-01-visual-neighbors-and-multi-select.md)

## 工具

| 工具 | 變更 |
|---|---|
| `get_anchor` | 接受 1 到 20 個選取。`anchor` 仍是第一個，新增的 `anchors` 依圖層面板順序列出全部；`selectionCount` 大於 `anchors` 的數量時，表示其餘的圖層藏在收合的群組裡。不再回報 `MULTIPLE_SELECTION`。 |
| `get_visual_neighbors` | 新工具。依畫面位置列出同一個父層裡的圖層，每個都附上方向、是否在同一列或同一欄、邊緣距離、位移與大小，單位是設計稿像素。 |

讀取屬性、截圖、匯出與相鄰元件，結束後都會還原使用者的選取，現在也包括同時選取的多個圖層。

## Figma 的實際行為

環境：Arc 1.166.0，已登入、檢視權限，英文 UI，使用者提供的私人測試檔。

### 多選

- 每個選取的圖層列都標上 `aria-selected`，畫布鍵盤目標顯示「N items selected」。
- 在圖層列上 Cmd 加點擊會加入單一圖層，Shift 加點擊會選取一整段範圍。還原多選時，先點第一個，其餘以 Cmd 加點擊加入；非 Mac 平台改用 Ctrl。

### 螢幕閱讀器的 mirror DOM

- 選取一個圖層後，mirror DOM 只放入五類圖層：父層、前一個同層圖層、選取的圖層、後一個同層圖層，以及選取圖層的第一個子層。
- 元素以相對父層的百分比定位，小數位很多，所以畫面上的位置是精確的，畫面外的圖層也有位置。
- 文字圖層不在 mirror DOM 中。
- Figma 工具列的縮放比例取整數百分比。縮到 5% 時，取整數本身就有約 10% 的誤差。

### 屬性面板的位置

- Top 與 Left 是相對最近的 frame，群組不算。動作按鈕在群組內的位置是 66，面板顯示 91，差額 25 正是群組在 frame 中的位置。
- 值為 0 的 Top 或 Left 會省略，例如 Frame 882 只列 Left 20。
- Auto layout 的子層，Top 與 Left 都不列，例如位置在 (25, 1) 的 Group 881。

## 做法

1. 選取參考圖層，讀取它在畫面上的位置與屬性面板。
2. 依圖層順序走過同層圖層。每次選取都會順帶放入前後兩個，所以每隔兩個選一次即可量完畫面上的位置。
3. 文字圖層逐一選取，改從屬性面板讀取位置。
4. 縮放比例取參考圖層在畫面上的寬度除以面板寬度，只有在它與工具列的數值差距超出取整數的誤差範圍時，例如圖層旋轉，才改用工具列的數值。
5. 統一換算到最近 frame 的設計稿座標：有面板位置的直接使用；只有畫面位置的，透過一個兩種位置都有的圖層換算。兩種都沒有的圖層，例如由 auto layout 決定位置的文字，列為未量測。
6. 依方向篩選；指定方向時，同一列或同一欄的優先，其次依距離排序。

## 驗證

| 項目 | 結果 |

| 資訊卡片，縮放 5% | 11 個同層圖層全部量到，約 0.5 秒。卡片 167×40；排行標籤在下方相距 10、位移 (0, 50)，大小 137.9×24.9，與屬性面板的 138×25、上 112、左 12 一致 |
| 動作按鈕 | 間隔群組從畫面量到，兩段文字從面板量到，在左側分別相距 3 與 39，約 0.7 秒 |
| 名稱文字當參考 | 透過動作按鈕換算，間隔群組在右側相距 36，動作按鈕在右側相距 39，約 0.7 秒 |
| 多選錨點，經由 MCP | 以 Cmd 加點擊選取兩個圖層後，`get_anchor` 依面板順序回傳兩個錨點；`inspect_nodes` 結束後兩個圖層的多選完整還原 |

## 未驗證

1. 修正後的相鄰元件經由 MCP 的完整路徑。Arc 裡的 extension 要重新載入才會是新版；縮放比例可為 null 的協定變更，也要重新啟動 MCP 伺服器才會生效。
2. Popup 在多選時的實際畫面；已有單元測試。
3. 被選取的圖層捲出圖層面板可見範圍時，多選能否全部找到；模擬清單的測試涵蓋了捲動。
