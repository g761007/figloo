# 同格式多倍率時只交回要求的倍率

狀態：修正完成，並在使用者的 Arc 上以 repo 的 MCP server 跑通完整鏈路  
日期：2026-10-06  
起因：另一個工作階段回報，對已有設計師設定的圖層要求 `png` 3x，拿回兩個檔案，`saveTo` 填檔名時失敗

## 問題

- 「Export」按鈕會匯出區塊裡的每一列設定。圖層本身已有同格式、不同倍率的設定時，臨時設定與設計師的設定會一起匯出，Figma 打包成 ZIP。MCP 原本只依格式篩選，所以兩個 PNG 都留下。
- 檔案多於一個時，`saveTo` 一律視為資料夾。填的是檔名時，MCP 會對這個路徑呼叫 `mkdir`：檔案已存在就回報 `EEXIST`，不存在則會建出一個以檔名命名的資料夾。
- 要求的倍率剛好與設計師的設定相同時，Figloo 會沿用那一列，不另外加臨時設定，但同格式的其他列仍然會一起匯出，所以同樣會拿回多個檔案。

## Figma 給的檔名

在 ZIP 裡，同格式第二個檔案的命名方式並不固定：

| 圖層 | 設計師的設定 | 要求 | ZIP 裡的檔名 |
|---|---|---|---|
| Frame 999:61586 | PNG 2x | PNG 1x | `<名稱>.png`（2x）、`<名稱>-1.png`（1x） |
| Frame 999:61586 | PNG 2x | PNG 3x | `<名稱>.png`（2x）、`<名稱>-1.png`（3x） |
| Group 763:22292 | PNG 1x | PNG 3x | 臨時設定的檔案是 `<名稱>@3x.png` |

推測：新增一列時，Figma 會先套用其他列沒用到的最小倍率。如果這個倍率是 2x 以上，Figma 可能會自動填入 `@2x` 之類的後綴，Figloo 改倍率時後綴也跟著改；從 1x 開始的列則沒有後綴，最後由 ZIP 用 `-1` 避免重名。這個推測沒有再查證，所以修正不依賴檔名。

## 修正

- Extension 把按下「Export」時的每一列設定（格式與倍率）傳給 MCP，放在 `ExportResult.settings`。這是選填欄位，所以 bridge protocol 不用改版：0.4.0 的 extension 不會送這個欄位，0.4.0 的 MCP server 則會忽略它。
- MCP 留下指定格式的檔案後，如果還有多個，就依倍率把設定列排序、依圖片寬度把檔案排序，取要求的倍率所在的那個名次。這只適用於 PNG 與 JPG，而且同格式的每一列都必須是 `Nx` 形式的倍率。有 `512w` 這類固定寬高的設定、SVG 或 PDF 時，不做挑選。
- 仍然有多個檔案、而 `saveTo` 帶有副檔名又不是以 `/` 結尾時，在寫入任何檔案之前就回報 `SAVE_REFUSED`，訊息會列出檔名，並請使用者改填以 `/` 結尾的資料夾。沒有副檔名的路徑照舊視為資料夾。

## 驗證

| 項目 | 結果 |
|---|---|
| MCP 單元測試 | 依尺寸挑出 3x 與 1x 的檔案，連同檔名中的 `-1`。有 `512w` 設定時兩個 PNG 都保留，`saveTo` 填檔名時回報 `SAVE_REFUSED`，原本的檔案不變。沒有指定格式、匯出 SVG 與 PNG 時，填檔名同樣被拒、什麼都沒寫入。改動前，這兩項分別失敗在拿回兩個檔案，以及回報中的 `EEXIST` |
| Arc：frame 999:61586，設計師的設定是 PNG 2x | PNG 3x 只交回 1179×2556；PNG 1x 只交回 393×852；不帶 format 時採用設計師的 2x，786×1704 |
| Arc：Group 763:22292，設計師的設定是 PNG 1x，即回報中的情境 | PNG 3x 只交回 `@3x` 那個檔案，240×30（圖層約 79×10），並存成指定的檔名；再存一次時回報既有檔案需要 `overwrite: true`；PNG 2x 為 160×20 |
| 設計師的設定 | 匯出後重拍兩個 root 的快照，與匯出前比對都是 0 個變更 |

## 未驗證

- 設計師用 `512w` 或 `512h` 設定，或同時有兩列 SVG 或 PDF 的情況，只由單元測試涵蓋。
- 上面對 Figma 檔名規則的推測。
