# 截圖不拍進協作者的游標與介面覆蓋物

狀態：完成，預定隨 v0.8.0 發布
日期：2026-11-24
依據：[盤點多個 frame 的計畫](../plans/2026-11-24-frame-survey.md)的 M1

## 發現

2026-11-24 在使用者提供的私人測試檔上實測（Arc，Chromium 158，檢視權限，英文 UI），`capture` 的整頁與單一畫面截圖都有兩個問題：

- 另一位協作者的游標與名字標籤出現在截圖中，蓋住設計，也把協作者的名字帶進了 agent 的對話。
- 「You can only view and comment on this file.」橫幅與底部工具列蓋在畫布上。高的畫面縮放到填滿時，底部被橫幅擋住一截。

[增量快照研究](2026-10-12-incremental-snapshot-research.md)也看過別人的選取框出現在截圖中。`snapshot_layer` 用同一套截圖流程，所以快照的截圖也有這些問題。

整頁截圖另有一個可以改善的地方：縮放到全覽後，畫面寬高比與內容不同，上下或左右留著大片空白，而截圖依長邊縮到 1568 px，空白也占了解析度。

## Figma 的 DOM

蓋在畫布上的元素，2026-11-24：

| 元素 | 選擇器 | 說明 |
|---|---|---|
| 協作者的游標與名字標籤 | `[data-testid^="multiplayer-cursor-"]` | 每位協作者一個，後面接著編號；名字在 `multiplayer_cursors--nameContainer--…` |
| 底部工具列與檢視權限橫幅 | `[data-testid="positioned-design-toolbelt"]` | `position: fixed` 的整條底列；橫幅與按鈕都在裡面，另有 `toolbelt-banner-close-button` |
| 留言標記 | `[class*="comments_view--outerAnchorContainer"]` | 涵蓋整個畫布的容器；class 帶雜湊後綴，所以用前綴比對 |
| 提示框 | `[data-testid="visual-bell-root"]` | 0.7.0 起已在截圖時隱藏 |

別人的選取框不在 DOM 中，應該是 Figma 畫在畫布（WebGL）上，CSS 無法隱藏。畫布右上角的頭像列（`multiplayer_view--pilePackedRight--…`）與畫布重疊幾十 px，但兩次整頁截圖都沒有出現，所以不處理。

## 改動

- 截圖期間加一條 CSS，以 `visibility: hidden` 隱藏上表的四種元素，截完（`finish_capture`）就移除。原本只隱藏提示框的 `hideToasts` 改名為 `hideOverlays`。`capture` 與 `snapshot_layer` 都適用。找不到這些元素時照常截圖，不影響結果。
- 整頁截圖（`capture` 不帶 `ref`）在 service worker 中找出內容範圍：畫布是截圖四邊內側最多像素共有的顏色，和它相差超過 4 的像素算內容；離邊緣 4 px 內的像素不算，避免面板的分隔線。內容範圍加上 12 px 的邊距後裁切；整個畫布都是空的時候照原樣。圖層截圖不變。

## 驗證

| 項目 | 結果 |
|---|---|
| 單元測試 | 隱藏與還原四種元素、畫布不受影響；內容範圍的邊距、接近畫布色的判斷、忽略邊緣的分隔線、空頁面。extension 223 項全部通過，typecheck 通過 |
| 真實的 Figma，截圖前 | 畫面上有一位協作者的游標、檢視權限橫幅、工具列與留言容器 |
| 整頁截圖 | 沒有游標、橫幅與工具列；上下的空白裁掉了，圖從 982×1568（縮小到 0.84 倍）變成 1135×1079，不必縮小 |
| 單一畫面截圖 | 一個圖示（縮放 2138%）與一個高的畫面（縮放 93%）都沒有游標；高的畫面底部不再被橫幅擋住 |
| 截圖之後 | 工具列、游標與留言容器都恢復顯示，沒有留下 CSS；選取與畫面都還原 |

## 沒有驗證

- 留言標記實際顯示時的隱藏：這次畫面上沒有留言標記，只確認了容器被隱藏。
- 別人的選取框：無法以 CSS 隱藏，列為已知限制。
- 登入版 canary 與訪客整合測試尚未重跑。
- 深色畫布或有圖案的畫布背景上的內容範圍判斷。
