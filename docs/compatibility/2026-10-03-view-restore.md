# 截圖與快照後還原畫面

狀態：實作完成，在使用者的 Arc 上驗證通過。`capture` 與 `snapshot_layer` 結束後，縮放比例與畫面位置都回到原處  
日期：2026-10-03  
範圍依據：[Roadmap 第一批](../plans/2026-10-02-roadmap-batch-1.md)的 M7。使用者的決定是只接受完整還原，也就是縮放比例加上畫面位置

## 可行性試驗的發現

| 項目 | 結果 |
|---|---|
| 讀出畫面 | 開啟「Adapt content for screen readers」後，mirror（`#hidden-input-activedescendant[role="main"]`）的第一層 div 是一個 1,000 設計像素寬的方框，左上角就是頁面原點。`left` 與 `top` 是原點在畫面上的位置（整數 px），`width` 除以 1000 就是精確的縮放比例：例如 2447.67px 代表 244.767%，縮放標籤顯示 245%。9 組觀察值都符合 |
| 更新時機 | 縮放標籤立刻更新；mirror 在畫面停止變動約 520 到 550 ms 後，一次更新到新的位置 |
| 縮放 | 在畫布上送出帶 `ctrlKey` 的 wheel 事件，會以游標為中心縮放 2^(−deltaY ÷ 50) 倍。deltaY 為 −60 時是 2.2974 倍，−100 時是 4.00001 倍，沒有上限；反向送出時，回到完全相同的位置 |
| 捲動 | 不帶 `ctrlKey` 的 wheel 事件，每單位捲動 2 px（這台機器的裝置像素比是 2）。每個事件沿移動方向最多 120 px：最初的試驗把兩軸各切成 100 px，斜向的事件因此被截短，多花了好幾輪 |
| 不能用的量尺 | Mirror 裡圖層元素的大小不一定是圖層的大小。沒有排版的元素只有標籤文字的大小（例如 60×32），縮放後也不變，所以不能拿來量縮放比例 |
| 合成事件 | Figma 接受程式送出的 wheel 事件。Figloo 判斷使用者介入只看真正的輸入（`isTrusted`），所以還原用的事件不會被當成使用者的操作 |

## 做法

- `capture` 開始時，等 mirror 的縮放比例與縮放標籤一致，再記下使用者的畫面，也就是原點位置與縮放比例。
- `capture` 截圖、還原選取之後，接著還原畫面。`snapshot_layer` 讀取期間，畫面必須停在 root，所以等所有圖層讀完、選取還原之後才還原。讀取失敗、時間用完，或使用者按下遮罩上的「Stop」時，也會還原。
- 每一輪先送出 wheel 事件，等 mirror 更新後再修正剩下的差距。放大時，先在較小的縮放比例下捲動，再放大；縮小時，先縮小再捲動。這樣捲動的距離比較短。每個捲動事件不超過 50 px。原點回到同一個整數像素，而且縮放比例相差不到萬分之一，就算還原。
- 每一輪都從結果推算每單位的捲動與縮放速率。其他瀏覽器的速率不同時，第二、三輪也能修正過來。最多 5 輪。
- 以下情況不還原，`viewRestored` 為 false：沒有開啟「Adapt content for screen readers」、使用者在途中操作 Figma、分頁在背景，或 Figma 沒有回應輸入。

## 驗證

環境：Arc，已登入、檢視權限、英文 UI，使用者提供的私人測試檔。新版 MCP 伺服器以 stdio 腳本在 47130 port 啟動。Root 是一個 90 層的 frame；每一輪先以 wheel 事件設定不同的起始畫面，再呼叫工具。

| 項目 | 結果 |
|---|---|
| 可行性試驗：以 wheel 事件還原 Shift+1 等改變 | 5 種畫面全部還原，縮放比例相同，誤差 0 px；最慢 1.9 秒，當時捲動切得太大 |
| 實作後，`capture`（圖層與整頁）與 `snapshot_layer` 共 5 輪，起始畫面從 75% 到 262% | 都回報 `viewRestored: true`。縮放標籤相同，原點誤差 0 px，縮放比例誤差最多 3.8×10⁻⁶ |
| 再跑 5 輪，同時在頁面中記錄還原送出的事件 | 都還原，誤差 0 px。還原本身花 528 到 1,080 ms，mirror 更新 1 到 2 次，送出 3 到 11 個 wheel 事件 |
| 分段讀取：以較短的時間上限把 90 層分成 4 次讀完 | 每次呼叫都從不同的畫面開始，4 次都還原，誤差 0 px |
| 讀取途中在遮罩上按 Esc，由頁面中的腳本送出 | 回報 `USER_INTERRUPTED`，畫面還原，誤差 0 px |
| 快照內容 | 每次都讀到 90 層，`alignment` 為 confirmed |

AppleScript 在 Figloo 讀取期間執行頁面腳本，要等約 9 秒才會執行，所以 Esc 是在快照開始前先裝進頁面的計時器送出的。

## 未驗證

- 使用者在途中操作 Figma 時不還原：由程式路徑與單元測試涵蓋，沒有在 Arc 上實測。
- 沒有開啟「Adapt content for screen readers」時回報 false：只由單元測試涵蓋，沒有為此改使用者的 Figma 設定。
- 其他瀏覽器、作業系統與裝置像素比的捲動與縮放速率：單元測試以不同的速率模擬，實機沒有驗證。
- [已知限制](README.md#已知限制)第 11 條提到 mirror 偶爾給出過時的位置。如果這發生在記下畫面與還原之間，還原的位置會跟著偏移；實測中沒有發生。
- 使用者在 `capture` 開始前不到 0.5 秒才捲動過畫面時，mirror 可能還沒更新，Figloo 會記下稍早的位置。縮放比例不一致會被發現並等待，只有捲動則無法分辨。
