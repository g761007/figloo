# 讀取時的遮罩與暫停

日期：2026-10-02  
狀態：已實作，三個階段完成並在 Arc 驗證，見[驗證紀錄](../compatibility/2026-10-02-reading-overlay.md)  
依據：使用者的需求，讓快照讀取期間不受干擾；相關的多工作階段企劃見[自動交接與身分顯示](2026-10-02-multi-session-handover.md)

## 情境

`snapshot_layer` 讀取一頁約 30 到 40 秒，最多 3 分鐘。這段期間 Figma 分頁必須留在畫面上，而且不能操作。讀完之後，`query_snapshot` 只讀快照檔，不需要 Figma 分頁。

目前讀取中可能被打斷的情況：

| 情況 | 目前的行為 |
|---|---|
| 在 Figma 裡點擊、按鍵或捲動 | 立刻中止，回報 `USER_INTERRUPTED`；收回展開的圖層，保留使用者的新選取 |
| 切到同一個視窗的其他分頁，或把視窗縮小 | Figma 在背景不接受選取與展開，讀取以 `TAB_IN_BACKGROUND` 中止；在背景也無法收回展開的圖層，選取不會還原 |
| 使用者不知道讀取正在進行 | 只能從圖層面板快速跳動看出來，不知道還要多久 |

## 目標與非目標

目標：

- 讀取期間在 Figma 頁面上顯示遮罩，說明正在讀取、進度與預估剩餘時間，並提供「停止」按鈕。
- 遮罩攔下誤觸的點擊與捲動，只有「停止」按鈕或 Esc 會中止。
- 分頁進入背景時暫停，回到畫面後從中斷的圖層繼續，不必重新讀取。
- 中止或逾時之後，在分頁回到畫面時收回展開的圖層、還原選取。

非目標：

- 阻止使用者切換分頁或視窗。這在 extension 中做不到，所以改用暫停與繼續。
- 讓讀取在背景進行。Figma 在背景分頁不接受選取與展開，這是 Figma 的行為。
- 其他工具的遮罩。`inspect_nodes`、`capture`、`export_asset` 都在幾秒內結束，遮罩一閃而過反而干擾。
- 快照時一併匯出圖檔。設計師設定過匯出的圖層每個要幾秒，會明顯拉長快照，另行評估。

## 設計

### 遮罩

- Content script 在讀取開始時加入遮罩，結束時移除。遮罩放在 closed Shadow DOM 裡，掛在 `document.documentElement` 下，`position: fixed`、蓋住整個頁面，z-index 高於 Figma 的對話框；樣式不會和 Figma 互相影響。
- 半透明背景，中間一張卡片：
  - 標題：Figloo is reading this page for your coding agent。
  - 進度：走訪時顯示已找到的圖層數；逐一讀取時顯示「已讀取 120 / 278 個圖層」與預估剩餘時間，預估以目前每個圖層的平均時間計算。
  - 說明：Keep this tab on screen. You can use other windows meanwhile.
  - 「Stop」按鈕。
- 文字用英文，與 popup、工具列提示一致；Figloo 目前只支援 Figma 的英文 UI。
- 無障礙：卡片的 role 是 `alertdialog`，進度放在 `aria-live="polite"` 的區塊；遮罩出現時，焦點移到「Stop」按鈕。

### 不影響讀取本身

- Figloo 選取圖層時，是直接把合成事件派發給圖層列，展開時派發給展開箭頭，不依賴滑鼠座標，所以遮罩擋不到。
- 圖層在畫面上的位置來自 mirror 的 `getBoundingClientRect`，和遮罩無關。
- 截圖：快照開頭約 3.5 秒的截圖階段不顯示遮罩，否則會被拍進截圖。遮罩在截圖完成、開始讀取時才出現。

### 使用者的輸入

- 落在遮罩上的點擊、滾輪與觸控，由遮罩攔下，不再算是使用者介入。現有的偵測會在 window 上看到這些事件，所以要依事件的目標排除遮罩。
- 焦點在遮罩的按鈕上，所以按鍵不會傳到 Figma。按 Esc 等同按「Stop」；其他按鍵忽略。
- 按「Stop」或 Esc：中止，回報 `USER_INTERRUPTED`，訊息說明是使用者按了停止。因為使用者的選取沒有被改動，所以會完整還原：收回展開的圖層、還原選取與捲動位置。這比點擊畫布的中止更乾淨，因此工具說明改為建議用「Stop」。
- 遮罩以外的輸入，例如 Figma 的頂部工具列或另一個 Figma 視窗，仍照現有規則中止。

### 背景時暫停

- 讀取中，Figma 分頁進入背景時，不再立刻中止：
  - 正在進行的那一步，例如選取一個圖層，等分頁回到畫面後重做。
  - 遮罩顯示「Paused: bring this tab back on screen to continue」。
  - 用 `visibilitychange` 事件等分頁回到畫面；因為背景分頁的計時器會被節流，所以不用輪詢。
- 時間上限 180 秒照常計算，暫停的時間也算在內。時間用完時以 `BUDGET_EXCEEDED` 結束。
- 分頁在背景時結束（逾時，或 MCP 端放棄），無法立刻收回展開的圖層。改為登記一次：分頁回到畫面時，收回 Figloo 展開的圖層並還原選取。如果使用者在那之前已經操作 Figma，就以使用者的操作為準，不再還原。
- 走訪階段只讀圖層列，在背景也能進行；遇到需要展開的圖層時才暫停。

### 進度的計算

- 走訪：已讀到的圖層數。
- 逐一讀取：第幾個與總數；剩餘時間取最近 20 個圖層的平均時間乘上剩餘數量，四捨五入到 5 秒。
- 遮罩每 250 ms 更新一次，避免頻繁改動 DOM。

## 階段與驗證

| 階段 | 內容 | 驗證 |
|---|---|---|
| 1 | 遮罩、進度、「Stop」與 Esc、排除遮罩上的輸入、截圖階段不顯示 | 單元測試：遮罩的建立與移除、進度文字、落在遮罩上的事件不算介入、Stop 回報 `USER_INTERRUPTED` 並完整還原。Arc 實測：點遮罩不中止、Stop 中止並還原、截圖中沒有遮罩 |
| 2 | 背景時暫停與繼續、背景中結束時延後收回 | 單元測試：以模擬的 `document.hidden` 驗證暫停、繼續與延後收回。Arc 實測：讀取中切到別的分頁再切回，讀取繼續完成；切走直到逾時，回來後圖層收回 |
| 3 | 工具說明、README、相容性文件 | 重新產生工具文件；README 說明讀取期間可以使用其他視窗、建議用 Stop 中止 |

每個階段完成後，經使用者同意再 commit。

## 風險

| 風險 | 緩解 |
|---|---|
| Figma 在 window 上監聽點擊，遮罩上的點擊仍讓 Figma 做出反應，例如關閉選單 | Arc 實測確認；遮罩在 capture 階段攔下並停止傳遞，對 Figma 掛在 window 的監聽則只能實測 |
| 遮罩被拍進截圖 | 截圖階段不顯示；截圖完成後才加入 |
| Figma 改版後 z-index 不夠高，遮罩被 Figma 的元件蓋住 | 使用允許的最大 z-index，掛在 `document.documentElement` 下 |
| 暫停太久，MCP 端先逾時 | 時間上限包含暫停時間，所以 MCP 的 200 秒逾時仍在上限之外 |
| 延後收回時，使用者已經切到別的頁面或檔案 | 收回前確認頁面與檔案沒變；不符就放棄 |

## 待決定

1. 遮罩的文字用英文，與目前的介面一致；是否需要繁體中文。
2. Esc 以外的按鍵是否也算停止。這份企劃只把 Esc 當作停止。
3. 遮罩的透明度：完全遮住設計稿，還是半透明讓使用者看得到讀取的過程。這份企劃採半透明。

## 使用者的決定，2026-10-02

1. 遮罩的文字：英文，與 popup、工具列提示一致。
2. 停止的按鍵：只有 Esc；其他按鍵忽略，避免誤按中止長時間的讀取。
3. 透明度：半透明，讓使用者看得到讀取的過程。
